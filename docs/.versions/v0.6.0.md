# Release Notes — v0.6.0

**Date:** 2026-05-26
**Type:** New Feature / Architectural Domain Expansion

## Summary

This release introduces a new "Maintenance" tracking domain to the CoolKonyha platform. It allows independent tracking of maintenance cases while sharing the product catalog database. This domain is fully isolated from the orders database, ensuring that status transitions, histories, and item lists remain separate and allow custom future expansion.

## Changes

### 1. Database Foundation
* **Migration Script:** [migrate_maintenance.js](file:///d:/dev/coolkonyha-solo-vibe/scripts/migrate_maintenance.js)
  * Renamed the shared `business_status_workflow` table to `order_status_workflow` to specialize it for the orders domain.
  * Created the four maintenance-specific tables:
    * `maintenance_cases`: Head record mirroring orders (`case_id`, `case_code`, `cust_id`, `current_status`).
    * `maintenance_items`: Line items linking cases to the products catalog (`case_id`, `prod_id`, `quantity`, `issue_note`).
    * `maintenance_status_history`: Immutable transition log for audit trails.
    * `maintenance_status_workflow`: Dedicated state configuration table (seeded with 9 states: `NEW`, `DIAGNOSED`, `PARTS_ORDERED`, `IN_REPAIR`, `TESTING`, `READY`, `INVOICED`, `CLOSED`, `CANCELLED`).
  * Seeded dummy maintenance case data.

### 2. Backend API Integration
* **DBRobot Logic:** [agent.js](file:///d:/dev/coolkonyha-solo-vibe/server/agent.js)
  * Updated existing order status logic to query the renamed `order_status_workflow` table.
  * Implemented new isolated CRUD/business methods: `createMaintenanceCase`, `addMaintenanceItem`, `updateMaintenanceStatus`, `getMaintenanceCases`, `getMaintenanceDetails`, and `getMaintenanceWorkflowStatuses`.
  * Enforced the **Dual-Write** (updating head status and status history transactionally) and **Pricing Continuity** rules in the new domain.
* **REST Endpoints:** [routes.js](file:///d:/dev/coolkonyha-solo-vibe/server/routes.js)
  * Added `/api/maintenance` endpoints:
    * `GET /api/maintenance` (list all cases)
    * `POST /api/maintenance` (create a case)
    * `GET /api/maintenance/:id` (retrieve details, items, history)
    * `PUT /api/maintenance/:id/status` (update workflow stage)
    * `POST /api/maintenance/:id/items` (add line items)
    * `GET /api/maintenance/workflow` (list stages)

### 3. Frontend & UI/UX Rollout
