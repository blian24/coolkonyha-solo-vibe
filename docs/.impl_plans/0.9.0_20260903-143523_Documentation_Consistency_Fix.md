# 0.9.0 — Documentation Consistency Fix

**Date:** 2026-09-03
**Trigger:** A documentation-only research pass (via `/code-review`-style findings, no code read at the time) flagged that the doc set described two contradictory "current architecture" narratives for the same system.

## What was done

1. **Resolved the two competing narratives against actual source code.** Traced `server/index.js` → `server/routes.js` → `server/robots/robot-*.js` imports directly. Confirmed:
   - The live, wired-up server uses the `server/robots/` split (5 domain files), not `server/agent.js`.
   - `server/agent.js` (36KB) still exists in the repo but is imported by nothing in production — dead code left over from before the v0.8.0 split.
   - `server/pista.js` and `server/robots/email-robot.js` are both fully implemented (real classes, real methods) but neither is imported/instantiated anywhere reachable from `server/index.js` — no route or scheduler wires them in yet. `pista-agent.md`'s "Planned — not yet implemented" status was wrong; the accurate status is "implemented, not yet integrated."
2. **Fixed the test harness's stale re-learn scope.** `tests/helpers/learner.js`'s `LEARN_SCOPES.integration` and `.e2e` read `server/agent.js` instead of the robot files `routes.js` actually depends on — the re-learn phase embedded in every test report was learning from dead code. Updated both scopes to read `server/robots/robot-*.js`. Left `unit` scope pointed at `server/agent.js` deliberately, since `tests/unit/agent.unit.test.js` tests `tests/helpers/agent-factory.js`, which is a hand-mirror of `agent.js` logic, not the live robot files — flagged this as a known test-architecture gap in `docs/tests/README.md` and `db_robot_code_structure.md` rather than silently changing test behavior.
3. **Updated all "current architecture" docs to point at the real file layout:** `docs/assistant_team/database-robot.md`, `db_robot_logic_tools.md`, `db_robot_code_structure.md`, `docs/architecture/api-routes.md`, `docs/architecture/database-schema.md`, `docs/assistant_team/pista-agent.md`, `docs/assistant_team/email-robot.md`. Business-rule content (Dual-Write, Pricing Continuity mermaid diagrams) was left as-is since it's still conceptually accurate — only location/status headers changed.
4. **Fixed the broken link** in `docs/architecture/README.md` (`database-agent.md` → `database-robot.md`) and added that README, plus the module map, to `SOLUTION_DESIGN.md`'s own index so it's reachable.
5. **Rewrote `SOLUTION_DESIGN.md`:** version header (was `v0.8.0`, VERSION file says `0.9.0`), architecture Mermaid diagram (now shows the robots split and marks PISTA/Email Robot as implemented-but-not-wired), Assistant Team table (added a Status column), Component Responsibility Matrix (agent.js → robots/*, Email Robot no longer marked "to be built"), Quick Reference code↔doc maps, and Tech Stack (React+Vite is the target/installed stack but the live UI is still the vanilla-JS template MVC — flagged as an open, pending-approval migration, not touched).
6. **Fixed reachability gaps** per the project's documentation-connectivity rule: added index links (mostly directory-level, to avoid the index itself going stale) for `docs/.impl_plans/`, `docs/.notes/`, `docs/.prompts/`, `docs/designs/design-01-oceanic-spec.md`, `design-02-oceanic_plus-initplan.md`, and the pre-v0.6.0 release notes (`v0.5.0`–`v0.5.3`).
7. **Fixed the `docs/app-description.md` / `docs/notes.md` index entries** to match the files that actually exist after the user's own cleanup commit (`64f1f16`): `app-description.md` → `docs/app-description-original.md`; the `notes.md` row was removed since that file was moved to `.trash/` (not part of the documentation set).

## Why

Docs described two different eras of the same system as both being "current," and the one artifact that's regenerated from real code state (the test re-learn report) corroborated neither narrative cleanly — it read `agent.js` (implying the monolith was still authoritative) while the module map and live imports both said the split was real and wired in. Left alone, `docs/assistant_team/*` and `SOLUTION_DESIGN.md` would keep steering future work (human or AI) at a file layout that doesn't exist.
