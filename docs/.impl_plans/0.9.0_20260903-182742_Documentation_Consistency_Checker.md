# 0.9.0 — Automated Documentation Consistency Checker

**Date:** 2026-09-03
**Trigger:** Follow-up to `0.9.0_20260903-143523_Documentation_Consistency_Fix.md`. The user asked for two things to prevent that class of drift recurring: (1) reduce duplication of file-location/status claims across docs, and (2) an automated check strong enough to verify not just that a referenced path exists, but that it's actually imported by the code it claims to describe.

## What was done

1. **Created `docs/architecture/module-map/status.json`** — a single machine-readable manifest declaring every `server/` file's wiring status (`live` / `not-wired` / `legacy-unused`). This is now the one place that fact lives; narrative docs link to it instead of independently restating it (addresses the duplication half of the ask).
2. **Created `scripts/check-docs.js`**, run via `npm run check-docs` and automatically before `npm test` (`pretest`). It performs 4 checks:
   - Every path in `status.json` exists on disk.
   - Every `server/**/*.js` file has a `status.json` entry (new files can't go undeclared).
   - **Reachability from `server/index.js`, computed by statically following relative ES module imports, must match the declared status exactly** — a file marked `live` that isn't actually reachable fails the build, and vice versa. This is the "stronger" check the user asked for — it doesn't just check a path exists, it verifies the file is really wired in.
   - Every `server/...`/`tests/...` path referenced from a "living" doc (anything outside `docs/.impl_plans/`, `docs/.versions/`, `docs/building-docs/`, `docs/.notes/`, `docs/tests/reports/`) must exist on disk. Historical/dated docs get a non-blocking warning instead, since they're accurate records of the state at the time they were written and shouldn't be edited to match current reality.
3. **Wired it into `package.json`** as both `check-docs` (standalone) and `pretest` (so `npm test` can't pass while docs are inconsistent, even if business-logic tests are green).
4. **Sanity-tested the checker** by deliberately mis-declaring `server/pista.js` as `live` in the manifest — it correctly failed with an exact, actionable error (`... is declared "live" ... but is NOT reachable ...`) — then reverted the manifest to the correct `not-wired`.
5. **Ran it against the existing doc set** — it immediately caught two real leftover issues from the previous session's manual fix pass that had been missed by hand: a stale `server/email-robot.js` path in `docs/assistant_team/email-robot.md` (should have been `server/robots/email-robot.js`), and two doc entries using unresolvable `server/robots/*.js` glob notation. All three fixed; reworded to prose/directory references instead of literal globs.
6. **Documented the mechanism** in `docs/architecture/module-map/index.md` (new "Single Source of Truth" section) and `SOLUTION_DESIGN.md`'s "How to Maintain This Documentation" section, including an explicit rule: when a `server/` file is added, moved, or deleted, `status.json` must be updated in the same change, or the checker fails.

## Why

The prior fix pass corrected the existing drift by hand, but didn't stop it from recurring — the same failure mode (a file gets moved/split, the change lands in the module map but not in every narrative doc or the test harness) could happen again with the very next refactor. The user specifically flagged that a further round of file-splitting is coming (partly for AI token-cost reasons, not just readability), so the fix needed to (a) not assume a fixed file layout, and (b) not rely on a human or a future Claude session remembering to update N places by hand — it needed to be enforced automatically. Manual discipline had already been the stated policy (CLAUDE.md §8.3, the docs connectivity rule) and it didn't prevent this drift the first time.

## Files changed

- `docs/architecture/module-map/status.json` — new. Source-of-truth manifest.
- `scripts/check-docs.js` — new. The checker.
- `package.json` — added `check-docs` and `pretest` scripts.
- `docs/architecture/module-map/index.md` — added "Single Source of Truth" section documenting the manifest and checker.
- `SOLUTION_DESIGN.md` — added the same policy to "How to Maintain This Documentation," plus a checklist item to run `npm run check-docs`.
- `docs/assistant_team/email-robot.md` — fixed a leftover stale path the checker caught (`server/email-robot.js` → prose description, avoiding a re-checkable but historically-accurate path).
- `docs/tests/README.md`, `SOLUTION_DESIGN.md` — reworded `server/robots/*.js` glob references (unresolvable as a literal path) to plain directory references.

## Verification result

- `node scripts/check-docs.js` → passes (11 server files, 73 docs scanned), 18 non-blocking warnings all inside dated historical docs describing an earlier, later-abandoned naming scheme (`agent-orders.js` etc. from a draft plan superseded by the actual `robot-orders.js` naming).
- `npm test` → 36/36 passing, `pretest` hook confirmed to run the checker first and block the suite if it fails (verified via the deliberate-breakage sanity test in step 4 above).
