# 0.9.0 — Retire server/agent.js, Add Dead-File Handling Rule

**Date:** 2026-09-03
**Trigger:** Resolving future-ideas item i-1 ("Decide the fate of `server/agent.js`") at the user's request, plus a new standing rule for how dead files get handled going forward.

## What was done

1. **Moved `server/agent.js` to `.trash/server/agent.js`** via `git mv` (history-preserving rename, not delete-and-recreate), following the repo's existing `.trash/` convention of preserving the original relative path under it (mirrors how `.trash/scripts/*.js` preserved the `scripts/` prefix).
2. **Removed its entry from `docs/architecture/module-map/status.json`** — it's no longer a `server/` file, so it's out of scope for the manifest.
3. **Updated every "living" reference to the old path** so nothing points at a file that no longer exists there: `tests/helpers/learner.js` (unit re-learn scope now reads `.trash/server/agent.js`), `tests/helpers/agent-factory.js` and `tests/unit/agent.unit.test.js` (doc-comment paths), `ui_design/js/services/dataService.js` (`@see` tag redirected to `server/robots/`), and the narrative docs `database-robot.md`, `db_robot_code_structure.md`, `docs/tests/README.md`, `docs/architecture/module-map/index.md`, and `SOLUTION_DESIGN.md`.
4. **Resolved future-ideas item i-1** by removing it from `docs/.notes/future-ideas.md` (per that file's own convention — an item is removed once acted on; `Next ID` counter stays at 5, the number is retired for good).
5. **Added CLAUDE.md §8.5 "Dead File Handling"** — a standing global rule: confirmed-dead files get flagged in the future-ideas backlog (§8.4) rather than moved/deleted unprompted; once acted on, they're moved (not deleted) into the project's established retirement location (e.g. `.trash/`) preserving relative path, via a VCS move, with every other reference to the old location updated — except historical/dated records, which are left as accurate history.

## Why

The user explicitly asked to resolve i-1 by moving the file into the `.trash/` folder they'd already established for this purpose in an earlier manual cleanup, and to encode this as a repeatable pattern rather than a one-off. Deleting outright would have been a harder-to-reverse action than the user asked for; moving preserves recoverability and matches the project's existing convention.
