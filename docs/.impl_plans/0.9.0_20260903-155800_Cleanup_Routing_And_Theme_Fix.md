## 3. `start.bat` Fix

### Problems
- Opened `http://localhost:5173` (Vite dev server → default React scaffold counter demo)
- Had no restart capability (old server process would block port 3001)
- Killed all Node.js processes on restart (too aggressive — would affect unrelated apps)

### Fix
- Now opens `http://localhost:3001` (Express server — the real app)
- Kills **only the process bound to port 3001** using `netstat`+`taskkill /PID` before starting
- Drops the `npm run dev` Vite launch entirely (app runs through Express only)

## 4. Theme Toggle Fix

### Problem
`toggleTheme()` was broken in all views except Dashboard:
1. Both `index.html` and `databaseController.js` defined `window.toggleTheme` — the controller version silently overwrote the better one on every Database view load
2. Both versions called `document.getElementById('theme-label')` — but `#theme-label` existed only in `dashboard.html`, causing a `TypeError` on every other view
3. No `localStorage` persistence — theme reset to dark on every page reload
4. The toggle button was embedded in view headers (`dashboard.html`, `database.html`), making it disappear when navigating away

### Fix — 4 files changed

**`index.html`**
- Theme applied from `localStorage` in `<head>` before first paint (no flash)
- `toggleTheme()` rewritten: self-contained, no external element deps, saves to `localStorage`, safely syncs settings checkbox if visible
- Permanent theme toggle button added to sidebar bottom — visible on every view
- `#theme-label` moved to sidebar — always in DOM

**`dashboard.html`** — removed duplicate `#theme-label` + `#theme-toggle` from header

**`database.html`** — same

**`databaseController.js`** — removed `window.toggleTheme` override (lines 59–64)

### Behaviour after fix
- Toggle works on every view, every time
- Preference persists across page reloads (default: dark)
- Settings view checkbox stays in sync (delegated correctly by `settingsController.js`)
